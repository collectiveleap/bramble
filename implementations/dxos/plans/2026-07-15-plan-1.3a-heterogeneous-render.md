# Phase 1.3a — Heterogeneous row render (read-only slice) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Let an outline row whose object is **not** a Bramble `Node` render via that object's own registered **`Section` Surface** (read-only), instead of forcing it through the text `RowEditor` — the first realization of BR-16's "a row renders by its type." Bramble `Node` rows are unchanged.

**Architecture:** One render branch at `OutlineRow.tsx:66` — `Obj.instanceOf(Node, row.node)` keeps today's `RowEditor`; otherwise render `<Surface.Surface type={AppSurface.Section} data={{ subject, attendableId }} limit={1} placeholder={fallback} />`. Pointer-drag / chevron / bullet / zoom chrome is already object-agnostic and unchanged. Editor-hosted keyboard gestures (split/merge/indent on a non-text row) are **out of scope** — deferred to 1.3b. `Node` stays the UI discriminator (BR-19 safe default).

**Tech Stack:** TypeScript (strict), `@dxos/echo` (`Obj.instanceOf`), `@dxos/app-framework/ui` (`Surface.Surface`, `useIsSurfaceAvailable`), `@dxos/app-toolkit/ui` (`AppSurface.Section`), Storybook (`@dxos/storybook-utils` + `withClientProvider`), Vitest, `moon`.

## Out of scope (1.3b and later)

- Keyboard gestures on non-text rows (split/merge are text-only; structural indent/reorder/zoom via keyboard need a row-level key handler outside CodeMirror — a new mechanism). Pointer-drag reorder/reparent already works on foreign rows unchanged.
- Cross-row focus/arrow-nav into a Surface row (the focus model assumes an `EditorView` per row).
- Editing a foreign object inline (the Section surface owns its own editing/reactivity; read-only here).
- The BR-19 A-vs-B decision (this slice works under either — it only needs `Node` to remain a distinguishable type, which both keep).
